# Repository Guidelines

## Project Overview

ScanUi is a .NET 10 desktop workspace built with Blazor and Photino for document scanning and organization. The current root screen is a demo: it displays in-memory sample pages and scanner settings, and does not connect to scanner hardware.

## Architecture & Data Flow

`src/ScanUi.App/Program.cs` creates the Photino host and mounts `App`; `App.razor` renders the icon sprite and routes to `ScanWorkspace`. The `/` page creates sample `WorkspacePage` records and passes them through `PageListPanel` to `PageThumbnail`. Preview, settings, and export components currently provide presentation markup. Reusable icons live in `src/ScanUi.App.Components`.

`docs/CODING_STANDARDS.md` defines the intended boundary: business rules belong in `ScanUi.Core`, while external integrations belong in separate `ScanUi.Adapters.*` projects. The current `src/ScanUi.slnx` contains `src/ScanUi.App`, `src/ScanUi.App.Components`, and two unit-test projects; it does not contain those Core/adapter projects or the standards' `ScanUi.Components` project. Preserve that distinction when adding code or moving components.

## Key Directories

- `src/ScanUi.App/` — Photino host, route/page UI, Tailwind source styles, and static web assets.
- `src/ScanUi.App/Pages/ScanWorkspace/Components/` — components used only by the workspace page.
- `src/ScanUi.App.Components/` — components shared by the app, including `SuiFolioIcon` and `SuiFolioIconSprite`.
- `src/ScanUi.App.Test.Unit/` and `src/ScanUi.App.Components.Test.Unit/` — workspace and shared-component tests.

## Development Commands

Run these from the repository root:

```sh
npm ci --prefix src/ScanUi.App
dotnet build src/ScanUi.slnx
dotnet test src/ScanUi.slnx
dotnet run --project src/ScanUi.App/ScanUi.App.csproj
```

The app's non-design-time build checks for Tailwind dependencies and runs `npm run build:css` automatically. Install them before building. No lint/formatter command or npm test script is configured; the `dotnet` commands above are standard CLI invocations, not repository-specific scripts.

## Code Conventions & Common Patterns

- Follow `docs/CODING_STANDARDS.md` for project boundaries, file/method size limits, component placement, accessibility, and test conventions.
- Keep Blazor markup in `.razor` files and C# state, lifecycle, and event logic in co-located partial `.razor.cs` files. Use constructor injection; avoid `@inject` and property injection.
- Expose component inputs as typed `[Parameter]` properties; mark required inputs with `[EditorRequired]`. Keep page-specific components beside their page and shared UI in the shared component project.
- Edit Tailwind inputs in `src/ScanUi.App/Styles/` or Razor markup. `src/ScanUi.App/wwwroot/app.css` is generated by the build and ignored by Git; do not hand-edit it.
- Keep UI presentation separate from business rules and device/integration code.

## Important Files

- `src/ScanUi.slnx` — solution project membership.
- `docs/CODING_STANDARDS.md` — normative architecture, Blazor, sizing, and testing rules.
- `src/ScanUi.App/ScanUi.App.csproj` — .NET target, project references, and Tailwind build hook.
- `src/ScanUi.App/package.json` and `src/ScanUi.App/package-lock.json` — Tailwind dependencies and CSS build script.
- `src/ScanUi.App/Pages/ScanWorkspace.razor` and `src/ScanUi.App/Pages/ScanWorkspace.razor.cs` — root route and sample workspace data.
- `src/ScanUi.App/Styles/app.css` — Tailwind CSS entry point and imported stylesheets.

## Runtime/Tooling Preferences

Use the .NET 10 SDK and Node.js 20+; the locked Tailwind Oxide package declares Node `>=20`, though the repository does not pin a Node version. npm is needed for Tailwind CSS generation; the desktop UI runs through the Photino host, not an npm development server. Use `npm ci` with the checked-in lockfile for dependency installation.

## Testing & QA

The two unit-test projects use xUnit v3 and bUnit. Tests render the workspace and shared components; follow the existing isolated `BunitContext` pattern. Run the full solution suite with `dotnet test src/ScanUi.slnx` after the app's npm dependencies are installed. Use concise Arrange/Act/Assert tests without external devices or services; use FakeItEasy for test doubles. Business logic in Core requires unit tests, and adapter boundary behavior belongs in that adapter's test project, per `docs/CODING_STANDARDS.md`.
